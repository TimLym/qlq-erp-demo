# 銓立光 ERP 前端 Demo

資安設備代理商 ERP 的前端示範，用於需求訪談後向客戶展示一期畫面設計。所有資料為 mock，不連後端。

## 啟動

```bash
npm install
npm run dev
```

開啟 http://localhost:5173 。右上角可切換示範身分（業務、業務主管、執行長、採購、財務主管、會計），代辦與待簽核清單會依角色變化。

到期項目（原「序號與授權」，導覽群組改「庫存與授權」）：序號是客戶的機敏資料，不記錄；`License { id, sku, name, qty, expires }` 只記項次的數量與到期日，一律由報價單項次產生，SO 抽屜不能新增也不能改。到期項目頁有類型篩選（授權／保固／維護合約／服務合約），欄位 客戶／SO（SO 可點，開 SO 抽屜）、類型、項目、到期日、剩餘天數，點一筆開 `LicenseDrawer`（負責業務、業務主管、執行長在這裡改到期日，`store.setLicenseExpiry` 寫流程紀錄）；SO 抽屜的授權項目列只能點，會跳到授權項目頁並開那一筆的抽屜（`?lic=`）；不是續約入口；原廠續約規則頁已從導航與路由拿掉（檔案保留）。續約項目（Pipeline／商機抽屜的續約自）改勾原 SO 的授權（id），續約商機第一版報價依授權數量帶項次。

到期項目（授權／保固／維護合約／服務合約；授權與證照是同一種）：`License { id, kind, sku, name, qty, start?, months?, expires }`。類型清單 `expiryKinds`（key、label、預設提醒天數）由系統管理員在「系統管理 → 到期類型」維護（使用中的不能刪）；提醒天數每人可在個人設定「到期提醒天數」覆寫（`store.remindDays`，記在瀏覽器），沒填就用類型預設。報價單內部項次多了「性質」（硬體／授權／維護合約／服務合約／單次服務）與「期間（月）」，舊資料沒填就用 `natureOf()` 依品名料號推。產生規則：授權→建立出貨單時登錄（起日出貨日、到期日預設出貨日＋期間，可改）；硬體→建立出貨單時自動產生保固（月數依料號 `warrantyMonths`，沒設 36；起日等驗收）；維護合約／服務合約→SO 成立時產生到期項目（起日等驗收）；單次服務（教育訓練、安裝、勘查）做完就結束，不產生到期項目、不設期限；客戶簽收（驗收）時，還沒起日的項目起日＝驗收日、到期日＝起日＋月數。首頁待辦「到期」改算 `store.myExpiring`（自己範圍內、剩餘天數 ≤ 提醒天數的項目），只有一筆直接開那一筆的抽屜。結案 SO「續約」建立的商機類型依第一筆到期項目：授權→授權案、維護合約／保固→維護案、服務合約→服務案，第一版報價帶性質與期間。

報價單內部項次：不再顯示供應商名稱（看下方廠商報價單區塊），用庫存的只標「使用庫存」；廠商報價單列表 hover 會把對應的內部項次點亮、點一下捲到第一條；授權、維護合約、服務合約的「期間（月）」必填（儲存草稿／客戶回簽都擋，沒填標紅），到期項目的到期日靠它算。
